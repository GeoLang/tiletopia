Features

Tiling Engine

  • OGC 3D Tiles 1.1 point-cloud tiles
  • Octree spatial partitioning with LOD
  • Parallel tiling (Rayon)
  • Optional GPU via wgpu
  • Draco/meshopt compression
  • Meshes tiled by mago-3d-tiler (MPL-2.0), bundled in the image, when TILETOPIA_MAGO_JAR is set
  • Without the jar meshes go to the native mesh tiler, which drops textures and materials and places the model from the upload's longitude and latitude
  • Vector files tiled by mago-3d-tiler only
  • IFC always read and tiled natively, placed from the upload's longitude and latitude or the IfcSite coordinates. DAE fails with an error naming the format

Input Formats

  • LAS, LAZ, E57, PLY: the native tiler
  • glTF, GLB, OBJ, FBX, CityGML: mago-3d-tiler when TILETOPIA_MAGO_JAR is set, the native mesh tiler otherwise, placed by the upload's longitude and latitude and without textures or materials
  • GeoJSON, GeoPackage, KML: mago-3d-tiler only, with optional longitude, latitude and crs upload fields
  • IFC: the native mesh tiler, placed by the upload's longitude and latitude or the IfcSite coordinates. crs is ignored
  • DAE uploads but fails: neither tiler takes it. Any other extension answers 400

Tile Server

  • REST API for asset management
  • View-dependent tile streaming
  • WebSocket presence, cursors, chat, view sync
  • JWT authentication (on by default)
  • CORS for CesiumJS
  • Multipart upload
  • 3D annotation layers, writes owner-or-admin

Terrain

  • Quantized-mesh from DEM files
  • Prebuilt ctb-tile bundles
  • SRTM fallback, 503 on failed download
  • Hillshade / slope / ndvi analysis tiles

2D Map Tiles

  • XYZ raster tiles (proxy + cache OSM)
  • MapLibre GL style JSON
  • TileJSON 3.0.0
  • Tile cache with TTL

Storage and deploy

  • Local filesystem, S3, GCS, Azure
  • Single binary, Docker
  • JWT roles admin / editor / viewer + per-asset ownership
  • Prometheus /metrics
  • Web dashboard with CesiumJS

Mounted routes that do not work

  • Scheduler never runs a job
  • Webhooks never deliver
  • STAC search returns one hardcoded item
  • COG offsets are fabricated
  • Temporal versioning, CRDT, federation, marketplace, AR/VR: modules with no callers

Ion is a hosted product. This is a binary you run. Scheduler, webhooks, STAC, COG, kriging, geoprocessing, indoor mapping and the rest of the premium routes are mounted and do not work. They are not scored.

vs Cesium Ion

  • Ion is cloud-only 3D Tiles hosting
  • This binary runs on your machine, AGPL-3.0
  • Point-cloud tiles and quantized-mesh terrain
  • Mesh, IFC and vector tiling are on the job queue

vs Potree

  • Potree is an open-source point-cloud viewer
  • This repo is a tiling server plus a CesiumJS dashboard
  • Output is OGC 3D Tiles 1.1, not Potree octrees

Architecture

tiletopia/
├── crates/
│   ├── tiletopia-core/       # Octree tiling engine, LOD, .pnts writer
│   ├── tiletopia-server/     # Axum REST API, WebSocket, JWT auth
│   ├── tiletopia-worker/     # Async tiling pipeline, job queue
│   ├── tiletopia-ingest/     # Point cloud, DEM and mesh readers
│   ├── tiletopia-terrain/    # Quantized mesh terrain generation
│   ├── tiletopia-store/      # Storage: local + S3 + GCS + Azure
│   └── tiletopia-cli/        # CLI binary (tile / serve / info)
├── gui/                      # Web dashboard (Vite + CesiumJS)
└── docs/                     # This page

Powered by sibyl, a Rust agent loop that calls an OpenAI-compatible LLM endpoint and keeps sessions in sqlite. It dispatches tool calls over HTTP to the GeoLang API, which runs 36 geospatial tools in-process (geocoding, isochrones, clustering, terrain profiles, environmental risk, routing). Sessions do not share memory, each one starts clean.

Quick Start

# Build from source
git clone https://github.com/GeoLang/tiletopia.git
cd tiletopia && cargo build --release

# Tile a point cloud
tiletopia tile --input scan.las --output ./tileset

# Start server
tiletopia serve --data-dir ./data --port 3000

# Docker
docker run -p 3000:3000 -v ./data:/data tiletopia serve --data-dir /data
