TileTopia

Self-hosted 3D Tiles server, an open-source alternative to Cesium Ion. It tiles point clouds, meshes, IFC and vector files, and serves quantized-mesh terrain.

Features

Tiling Engine

  • OGC 3D Tiles 1.1 point-cloud tiles
  • Octree spatial partitioning with LOD
  • Parallel octree build (Rayon)
  • meshopt simplification builds the lower LODs of a mesh tile. Tile geometry is compressed with EXT_meshopt_compression by default, or KHR_draco_mesh_compression on request. Textures can be written as KTX2 through KHR_texture_basisu
  • Meshes read and tiled natively, with their UVs, diffuse textures and diffuse colours, placed from the upload's longitude and latitude
  • A tile holding part of a textured mesh carries the crop of the texture its triangles reach
  • Vector files tiled by mago-3d-tiler (MPL-2.0) only, bundled in the image, needing TILETOPIA_MAGO_JAR
  • IFC placed from the upload's longitude and latitude or the IfcSite coordinates

Input Formats

  • LAS, LAZ, E57, PLY: the native tiler
  • glTF, GLB, OBJ, FBX, DAE, CityGML: the native mesh tiler, with textures and materials, placed by the upload's longitude and latitude
  • Zip of geotagged JPEG photos: reconstructed by OpenDroneMap on a NodeODM server you run, then the native mesh tiler
  • GeoJSON, GeoPackage, KML: mago-3d-tiler only, with optional longitude, latitude and crs upload fields
  • IFC: the native mesh tiler, placed by the upload's longitude and latitude or the IfcSite coordinates. crs is ignored
  • DAE must be COLLADA 1.4.1 with triangles or polylists, and anything else fails naming the reason. Any other extension answers 400
  • GeoTIFF, HGT and DTED rasters are tiled to a quantized-mesh terrain bundle
  • Georeferenced GeoTIFF, COG, JPEG, PNG and JPEG 2000: XYZ map tiles and TileJSON, reprojected to web mercator. JPEG and PNG need a world file or bounds, and a crs. JPEG 2000 needs the jp2 build feature, and takes GeoJP2 or GMLJP2 boxes in place of those fields

Tile Server

  • REST API for assets, tiling jobs and access control
  • tileset.json and tiles for CesiumJS or any 3D Tiles client
  • WebSocket presence, cursors, chat, view sync
  • JWT authentication (on by default), tokens from signup and login, good for 24 hours
  • CORS for CesiumJS
  • Multipart upload
  • 3D annotation layers, writes owner-or-admin
  • Export jobs: 3D Tiles zip, LAS/LAZ, terrain bundle, GeoJSON, PNG, CityGML, OBJ, GLB, and an offline viewer bundle zipping the tileset with a CesiumJS page. That page loads CesiumJS from cesium.com unless TILETOPIA_CESIUM_DIR names a build to copy in

Terrain

  • Quantized-mesh from DEM files
  • Prebuilt ctb-tile bundles
  • SRTM fallback, 503 on failed download
  • Hillshade / slope / ndvi analysis tiles
  • One op over a bbox as a COG download

Vector Tiles

  • GeoJSON, FlatGeobuf or CSV built into PMTiles with tippecanoe
  • Served as MVT under /martin, with TileJSON per source
  • Operator archives from TILETOPIA_PMTILES_DIR
  • Needs the martin cargo feature, which the Docker image has

Storage and deploy

  • Local filesystem
  • Single binary, Docker
  • JWT roles admin / editor / viewer + per-asset ownership
  • Prometheus /metrics
  • Web dashboard with CesiumJS

What does not work

  • Implicit tiling compiles and is not called when a tile is written

vs Cesium Ion

  • Ion is 3D Tiles hosting, in Cesium's cloud or as the commercial Cesium ion Self-Hosted
  • This binary runs on your machine, AGPL-3.0
  • Point-cloud tiles and quantized-mesh terrain
  • Mesh, IFC and vector tiling are on the job queue

vs Potree

  • Potree is an open-source point-cloud viewer
  • This repo is a tiling server plus a CesiumJS dashboard
  • Output is OGC 3D Tiles 1.1, not Potree octrees

Architecture

tiletopia/
├── crates/
│   ├── tiletopia-core/       # Octree tiling engine, LOD, .pnts and .glb writers
│   ├── tiletopia-server/     # Axum REST API, WebSocket, JWT auth
│   ├── tiletopia-ingest/     # Point cloud, DEM and mesh readers
│   ├── tiletopia-terrain/    # Quantized mesh terrain generation
│   ├── tiletopia-store/      # Storage: local filesystem
│   └── tiletopia-cli/        # CLI binary (tile / serve / info / validate / set-role / edge)
├── gui/                      # Web dashboard (Vite + CesiumJS)
└── docs/                     # This page

Other /api/v1/* routes that work on request input: STAC search proxies an upstream catalog, COG windows read range requests, static maps render the DEM, geostatistics interpolates posted samples, geoprocessing runs buffers, simplification and overlays, webhooks deliver HMAC-signed events, the scheduler runs the jobs it stores, and API keys authenticate read routes. Routes that answer fixed example data are listed under "What does not work" above and in the README.

Chat Agent

The chat agent is not part of this server. sibyl runs the agent loop against an OpenAI-compatible LLM endpoint and keeps sessions in SQLite, the GeoLang API runs the geospatial tools, and ViewTopia is the viewer it drives. This repository's dashboard has no agent chat. Its only chat is the message box in the collaboration panel, sent over the realtime websocket.

Quick Start

# Build from source
git clone https://github.com/GeoLang/tiletopia.git
cd tiletopia && cargo build --release

# Tile a point cloud
tiletopia tile --input scan.las --output ./tileset

# Start server
TILETOPIA_ION_BASE_URL=http://localhost:3000 TILETOPIA_JWT_SECRET=$(openssl rand -hex 32) tiletopia serve --data-dir ./data --port 3000

# Docker
docker run -p 3000:3000 -e TILETOPIA_ION_BASE_URL=http://localhost:3000 -e TILETOPIA_JWT_SECRET=$(openssl rand -hex 32) -v ./data:/data ghcr.io/geolang/tiletopia
